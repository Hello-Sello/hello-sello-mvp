Before you start

Four things that are true of nearly every table

Learn these once and roughly a third of every column list stops needing explanation. In the detail panels these columns are greyed out, so you can skip past them.

Nothing is ever deleted

Instead of removing a row, we stamp deleted_at with the time. The row stays for the audit trail; the app just hides it. This is called a soft delete.

Every row is signed

created_by / updated_by point at the person who did it, and created_at / updated_at record when. So we can always answer "who changed this?"

IDs are random, not counted

Every id is a UUID — a long random string like a3f9…, not 1, 2, 3. Nobody can guess the next one, and two databases never collide.

metadata is the spare drawer

A free-form JSON field on most tables for extras we haven't given a proper column yet. Handy, but nothing important should live there long-term.

How the whole thing hangs together

Not in the database

Where the files live

Photos, licences and PDFs are too big for a database, so they sit in five storage buckets. The database only keeps the file's path — a pointer to where it lives.

BucketWho can see itMax sizeWhat goes in
avatarsanyone with the link5 MBProfile photos, company logos and cover images. Public on purpose — they show on shop pages.
shop-mediaanyone with the link10 MBProduct photos and shop-page attachments, including PDFs like a spec sheet.
