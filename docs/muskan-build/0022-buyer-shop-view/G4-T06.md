inherited, rather than repeated per policy.

## ▶ AC 6 — price never leaks. Proven at five layers.

The structural reason it holds: **the connection override attaches to `profile_visible` only.**
`price_public` is a separate, un-overridable conjunct in every object.

Live `product_public_select`:
```
(profile_visible = true OR is_connected_to_company(company_id))
  AND (visibility_start IS NULL OR visibility_start <= CURRENT_DATE)
  AND (visibility_end   IS NULL OR visibility_end   >= CURRENT_DATE)
  AND is_caller_verified()
```
Live `current_pricelist_item` public arm — note `AND p.price_public` as its own conjunct:
```
(p.profile_visible OR is_connected_to_company(p.company_id))
  AND … AND p.price_public AND is_caller_verified()
```
Live `get_discoverable_shop` projection — the price is gated by a `CASE`, not by the row filter:
```
case when p.price_public then v.price_per_gram end,
case when p.price_public then v.tiers          end
```

# ▶ RULE ON THESE

### 1. The location filter's **shape** differs from the prototype *(P5 + P6 — never put to you)*
You ruled the dropdown's **presence** at T05's G4 (walk row 12: *"the rule is driven by what the
VIEWER sees, not by role"*). What was never ruled is that the live page uses a **dropdown +
location group headers** where the approved prototype used a **flat 4-up grid under a pill-tab
row**. With 2 locations and 6 products, Bob gets two banded sections and a half-empty Montreal row
(shot `15b`); the prototype showed one clean 4-up run (shot `26b`).
**Options:** (a) accept the live shape and mark the prototype superseded on this point ·
(b) flat grid + filter, matching the prototype · (c) keep grouping but only above N locations.

### 2. Criterion 5 names a state the schema cannot hold *(wording, not behaviour)*
The criterion reads *"when a connection is **pending**, the buyer shall see only what the seller
made visible."* There is **no `pending` in `relationship_status`** — the lookup holds exactly
`active`, `ended`, `suspended`. A pending connection lives in `pending_inbox_item`, a different
table. The **behaviour is correct** (Eva holds a pending `connect` and sees 4), but the criterion
as written describes a `relationship` state that cannot exist, and a future reader could "fix" it
by adding one.
**Options:** (a) reword to *"a connection request that has not been accepted"* · (b) leave it and
accept the ambiguity · (c) reword **and** note the two-table split in the ADR.

### 3. The buyer is never told **why** the catalogue grew *(P8 + P9)*
The prototype carried two cues that did not ship: the counter *"6 products · full catalogue
(connected)"*, and the per-product line *"Asks about X — the seller answers in chat"*. Live, Bob
sees six products with no indication that two of them are visible **only because he is connected**
— and a `Request pricing` button with no statement of what pressing it does. This is the whole
point of T06 going unsignalled at the surface.
**Options:** (a) accept — the green `Connected — go to chat` banner is signal enough ·
(b) restore the counter only (small, `ShopView`) · (c) restore both · (d) file for T08.

### 4. `region` and `location` disagree on AUR-1D *(seed data, surfaced by T06)*
`AUR-1D` renders `Region · Toronto` while sitting under the **`Montreal Warehouse`** group header
(shot `18`). Two independent columns — `region` is a product origin spec, `location` is the shelf —
but T06 is what first puts them side by side on one screen for a buyer, and they read as a
contradiction. **Not a T06 defect; seed data.**
**Options:** (a) fix the seed so the two agree · (b) accept — they are genuinely different facts ·
(c) rename the spec row (`Region` → `Origin region`) so the collision is impossible to misread.

### 5. `anon` retains INSERT/UPDATE/DELETE/**TRUNCATE** on `product_media` *(criterion 9 met narrowly)*
Criterion 9 asked for **SELECT** to be gone, and it is. But `anon` still holds every **write**
privilege on that table. This is exactly the T11 class already filed at T09's gate (`anon` holds
TRUNCATE on ~90 tables; not reachable via PostgREST, so not a live exploit).
**Recorded here because T06's own criterion touched this table's grants and stopped at SELECT.**
**Options:** (a) leave to T11 as filed · (b) widen T11 to "revoke all anon table writes" and
reference this · (c) close `product_media`'s writes in this slug since the migration is already
open on that table.

### 6. The G2 visual contract no longer exists *(cannot-verify, stated rather than waived)*
The approved contract was the **in-app** route, deleted at `/build` as its NOTES instructed. Every
prototype row above is therefore judged against the **HTML** variant A, which the same NOTES call
insufficient (*"a hand-drawn card cannot prove that claim"*). Rows P1–P4 are unaffected — they are
behavioural and I verified them on real data. Rows P5–P9 are **shape** judgements against the
weaker artifact.
**Options:** (a) accept — T02's G4 already proved component reuse by measurement ·
(b) have me re-stand the in-app route temporarily and re-shoot P5–P9 against it ·
(c) rule P5–P9 on the live page alone and retire the HTML prototype.
