# Connect · Deal card (screen ①) - prototype notes

**Throwaway prototype.** Built 2026-06-06. **LOCKED 2026-06-06** (Ayush). Light theme, slate + pink-600, reuses the Connect shell.
Run: Claude Preview config `dealcard-prototype` (port 8769), or `python3 -m http.server 8769 --directory _workshop/dealcard-prototype`.

## Question this answers

What does the Deal card look like and how does it behave - one card that works for both a buyer's
purchase order and a seller's sales order, shown to two roles (seller vs buyer) who must see different
numbers, placed inside the chat without crowding Sella out?

## Locked design (2026-06-06)

- **Decided look** - the card design itself is locked (front layout + back layout + line-item products + flip).
- **Role-based views, no toggle.** The seller sees a **Margin** field; the buyer sees a placeholder metric
  (name TBD). The app serves each role its own view - the buyer's app never even receives the margin value.
- **PO card / SO card via `doc_type`.** One `deal_card` entity with a `doc_type` discriminator:
  a **PO card** (purchase_order, buyer -> seller) or an **SO card** (sales_order, seller -> buyer).
  "Two card types under one entity" - the type = who authored it.
- **Front = facts, back = SIGNALS.** Front holds the deal facts; the back holds per-viewer SIGNALS
  (Choco-AI-style insights, generated by Deal-Sella, different for each side).
- **Half-card = a pre-connection gate, shown in the inbox only.** In the chat the card is **always full**.
- **Products = a line-item list** with a small square thumbnail on the left of each row. (The thumbnail will
  later open that product's own card - not built yet.)
- **Pinned-box + deal-selector chat placement.** A deal selector ("Talking about: [current deal]", defaults to
  the current deal) + a pinned deal box at the top of the chat -> click -> the card opens (flip / close).
  Sella stays in the right panel (no swap, no floating card).
- **Flip control = top-left.** Git-style version history on the card.

## Data model (PO card / SO card)

One `deal_card` record, `doc_type` discriminator (`purchase_order` | `sales_order`) = the two card types from
ONE entity. `margin` is **seller-scoped** (role-based, enforced at the data layer via RLS - not a UI hide).
Products come from `deal_line_item` (name, cultivar, volume, unit_price, pzn). `deal_card_version` = git-style
version history. `order` carries the PO# / SO# / Hello-Sello deal number / QR, generated at confirmation.
